(no selection), so the test could not have passed after the change; it was corrected in 9e6a3f9 to the context after an answer that next-questions.test.ts uses, and it fails on the code before the change (source "plan"). Commits 522254d and a17ca2c say "D-H043 item 4" and "item 5" where they mean the findings P11-U-04 and P11-U-05 (the decision has four items, all eight findings under item 1); the code comments were corrected in d016a68, the commit messages are left as they are. A first try to probe the rule from a scratch vitest file with `--root /` scanned far too much and was stopped; the probe was rerun with Node directly.

## Limits / confounders

The frozen sets contain no question that names another gene of the build, so their identical scores show that nothing else changed, not that the new sentence is right; that rests on the unit tests and the browser check. The rule still detects only the gene symbols its patterns know: on the HBB set "Show SLC6A3" is not refused as a foreign gene (it falls to "not one of the supported commands"), and HBB is not detected on another set; D-H043 changed the wording, not the detection. For a gene outside the build the sentence still ends "only <OPEN> is", true of the page and not of the build, as decided. Since D-H029 answer 88 no model suggestion is offered, so the "AI" mark kept for a model's plan is not shown anywhere in this build. Chrome only, one machine; usability itself is still not tested with people (D-H031).
