## Methods

The measurement was made with HTTP requests that set an Origin header, outside a browser. The responses are recorded verbatim in `research/raw/cors/cors-results.txt`.

## Raw results + uncertainty

| Source | Preflight | GET with Origin |
|---|---|---|
| Ensembl, Ensembl GRCh37 | 200, `*` | 200, `*`; no exposed headers |
| UniProt | 204, `*` | 200, `*`; release headers exposed |
| RCSB Data API | 200, `*` | 200, `*` |
| RCSB files (files.rcsb.org) | **403** | 200, `*` |
| RCSB ModelServer | **preflight lacks Access-Control-Allow-Origin** (per `docs/data-source-registry.md`) | 200, `*` |
| AlphaFold DB API and files | 200, `*` | 200, `*` |
| NCBI E-utilities | 200, `*` | 200, `*` |
| Reactome | 200, `*` | 200, `*` |
| Open Targets (POST) | 200, echoes the Origin | 200, echoes the Origin |
| HGNC | 200, but no allow-headers (per registry) | 200, `*` |
| PDBe | 204, `*` | 200, `*` |
| InterPro, QuickGO, GO | 200, `*` | 200, `*` |

Uncertainty: one observation per source. CORS is documented only by Ensembl and PDBe; for the others it is observed behaviour that can change without notice (`docs/data-source-registry.md`).

## Failures

**Negative findings:**
- the preflights of files.rcsb.org, models.rcsb.org and HGNC fail;
- Ensembl exposes no response headers, so browser code cannot read `Retry-After`.

## Limits / confounders

- Measured outside a real browser.
- CORS on error responses (429, 5xx) was not tested (`docs/scientific-validation.md` §6).

## Interpretation

Supported, with constraints. Every source can be called from a browser if the request stays a simple GET: no custom headers, and the Ensembl content type passed as a query parameter. Back-off against Ensembl must be blind.

## Decision

**Continue.**
- The curated journey works offline from bundled data.
- Live calls are an enhancement behind adapters with timeouts, retries and a per-source token bucket (`docs/data-core.md` §4).
- In the browser, NCBI calls send `tool` only.
