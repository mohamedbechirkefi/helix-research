## Integrity

Nothing under `research/benchmark/phase10/` or `phase10-heldout/` was edited; S15 and S16 differ only on the allowlisted units. `data/curated` is unchanged. No app file changed between the run and the reruns. A fresh `npm run web:build` before the reruns produced the same seven asset names as the build of record. The tracked shot folders that the suites rewrite were restored with `git checkout`.

## Method

One script ran every check in sequence and printed `<check> <exit> <time>`, with each check's output in its own log. The order was:
1. the builds;
2. the web frames and budgets;
3. the desktop measurement;
4. the Chrome suites;
5. the Firefox and Safari record runs;
6. unit tests and science, the supply chain and the desktop suites;
7. the DMG checks;
8. last, the release build, S31, S30 and the served build on the local static host.

Each failure was diagnosed from its log, and the affected steps were rerun on the same build. Two failures were not harness faults: the Firefox WebGL count and the desktop frames. The Firefox count got an interleaved A/B against the Phase 11 gate build (09334b1), built in a temporary worktree against the current research packages and removed afterwards.

## Uncertainty

One machine; one run per check, except the reruns stated. The reruns ran with the machine busy: load 2.7 to 8.7, a VS Code renderer near one core, and macOS's mediaanalysisd and CacheDelete. None of these was started or stopped by the run. The desktop frame result has no A/B against the gate's desktop build, so load and build are not separated. The Firefox A/B used the current research packages for both builds, so it tests the app code, not the research pin. With 10 loads per build, 6 against 7 does not distinguish the two rates.

## Interpretation

Exit criterion 3 holds: every judged check passes on the build of record under the gate's pass rules. The four harness corrections follow behaviour that P12.1.2 and rules version 8 meant to change, plus one invocation error of mine. Two open notes go to the limitations document:
- P12-BOR-01: Firefox's second WebGL context, which predates Phase 12;
- P12-BOR-02: the single mid-move desktop frame under load, cause not established.
