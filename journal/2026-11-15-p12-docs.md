## Method

The commands the READMEs document were run in order on fresh clones, each read by its exit code: `journal/results/clean-clone-p12221.log`. A second pair of clones tested the install order, with helix-app installed while the sibling helix-research was cloned but not installed. The e2e suites, the desktop build and the DMG were not run; the READMEs say so.

The documents were drafted by three parallel AI agents, each owning separate files, and reviewed by the coordinating session:
- helix-app `docs/portfolio-case-study.md`;
- helix-app `docs/diagrams/` (four SVGs and a mapping README) and `docs/product-vision.md`;
- both READMEs.

The review checked:
- a sample of the case study's figures against `paper/claims.md`;
- every file and function the diagrams name, against the code;
- the README prerequisites against `package.json`.

## Findings

- **Install order.** helix-research must be installed (`npm ci`) before helix-app is tested or built: the research packages, linked by path, resolve their own dependencies from helix-research's `node_modules`. No document stated this before; both READMEs now do.
- **Preview port.** `npm run web:preview` is fixed to port 5190 with `--strictPort`. The README gives the form verified on another port.
- **Stale figures.** The case study draft found figures that later builds superseded. `docs/known-limitations.md` section 2.4 gave the Phase 11 bytes at rest; it now gives the build of record's 1,976,426 bytes (vite preview) and the static host's figures. The on-screen text count went from 9,221 at the Phase 11 gate (C187) to 9,126 on the build of record; the case study states both. The cause of the drop is not established.

## Uncertainty

One machine. The clone was taken from the local repositories at their current commits, not from the remotes.

## Interpretation

The hypothesis holds once the install order is stated: from a clean clone, every documented step exits 0, and the counts equal the build of record's.
