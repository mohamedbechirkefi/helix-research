## Methods

One shell script per run executes every check in sequence and prints `<check> <exit> <time>`; each check's output goes to its own log. Order: the builds (web, desktop, DMG), the web frames and budgets first (the most load-sensitive), the desktop measurement, the web suites, unit tests and science, supply chain, desktop suites, DMG checks. The preview server (`vite preview`, 127.0.0.1:5191, host name `helix-web.test` allowed for the non-development host checks) is started and stopped by the script. Frame breaches get the one automatic rerun of D-H038 (web) and D-H047 (desktop).

The first run (0f13b2e) failed four checks: S20, S22 soak and p11-new-budgets (exit 1), and S23 compare (64, my invocation). S22 and the content part of S20 were harness faults, fixed in 8d4a56c; p11-new-budgets and S23 were my invocation errors (a preview not allowing the host name; a compare script that needs two folders, then an unquoted shell variable that rebuilt HBB from the older fixtures). S20's budget failure at 6x CPU remained after the harness fix and was a product regression. The author chose to bisect, fix and rerun the gate (D-H049).

Regression method: an interleaved A/B of `node e2e/tiers.mjs --only=select --conditions=cpu6` between the gate build and the D-H036 build (e010967), three rounds; `git bisect run` over e010967..0f13b2e in a separate worktree, a commit counted bad at 2 or more frames over 33.4 ms in the drag and wheel moves over three pages; then three variant builds of 8d4a56c, each interleaved with an unmodified build for two rounds: v1 (the focus call removed), w2 (the synchronous render removed), x3 (the committed fix). Then the pin, the fix, and the whole suite again (tag p11gate2).

Constant: the curated data, the rules (version 6), prompts, budgets, the suite's commands and pass rules.

## Failures

- My invocation errors in the first run: the preview bound to `localhost` refused `helix-web.test` (p11-new-budgets, 5 harness errors); `npm run compare:hbb` needs two folders (exit 64); an unquoted zsh variable passed `--fixture-set hbb/curated` as one word, so HBB was rebuilt from the older fixtures (58 differences) until the arguments were written out (16).
- The first A/B attempt used `--only=none`, which runs no frame condition; its six empty result files were deleted by name and the A/B rerun with `--only=select`.
- The first rerun of S20 used the first run's tag, so the first run's `tiers-p11gate.json` was overwritten by the rerun's; the first run's log keeps its lines.
- The summary step of the variant script failed twice on a retag that missed its Python tuple (NameError); the measurements were read from the result files directly.
- My error in the browser run: it reused the gate's tag `p11gate2`, and the suites S6 to S8, S10 and S11 do not add the browser to their result file names. Firefox's results then Safari's overwrote the gate's Chrome result files for S6, S7, S8, S10 and S11, and Firefox's S12 overwrote Chrome's (Safari's S12 and both browsers' S9 and S13 stopped before writing). These files had not been committed, so the gate's own JSON for those six checks is lost; the gate's logs in `run2/` keep their output and exit codes. The overwritten files were renamed to the browser that wrote them (by modification time: Safari 15:08 to 15:24, Firefox 14:48), the six Chrome checks were rerun on the same build with tag `p11gate2r`, and Firefox's lost files were rerun with tag `p11gate2-firefox`.
- The bisect's first bad commit names both the focus move and the synchronous render; only the variants separated them.

## Interpretation

The agreed suite and budgets pass on the build of record, so criterion 1 and 2 of the plan's section 1 hold, with the expected exits stated. The regression shows that S20's 6x condition catches what the other suites do not: the change it caught was an accessibility fix, every functional and accessibility check passed with it, and only the slowed frames moved. The cause in the code is established by the variants; the mechanism (why a synchronous render at Skip makes moves 20 s later heavier) is not, so a similar change could return unnoticed in any path S20 does not drive. The margins remain thin: the web frame median sits at 16.7 to 16.8 ms against 16.8 ms, and bytes at rest have 24,695 bytes of room.
