## Methods

- **Integrity order (invariant 1).** (1) Characterisation tests pinned every prompt version's hash, the exact v5 messages of the app context and the D-H010 cue reading (34a1c8c; helix-app 6d75100). (2) The D-H011 held-out set `research/benchmark/routing-heldout-dh011.jsonl` (21 items RN01 to RN21, oracles and expected worlds) was written and committed alone (83aab15, 2026-11-02 22:27:57 +01:00) before any draft existed and before any model call with a draft; no benchmark, held-out or test wording is reused, and none of its wordings went into any draft. (3) Drafts were iterated on the development items only: the D-H010 items RM01 to RM16 and the D-H008 routing held-out RH01 to RH17, both already seen with v5 output. The runner refuses `--prompt-draft` on the D-H011 file. (4) One draft was frozen as prompt v6 (hash-pinned; v1 to v5 unchanged and still served to their contexts) and run once on the D-H011 set; that result is reported as is.
- **Harness.** `OllamaProvider` gained a benchmark-only `messages` option (the app never sets it); `run.ts --prompt-draft` swaps the draft's rules for RULES_V5 in the system message and its hint for v5's answer hint in the user message; context, validation and the world-cue check are unchanged. `make-draft.ts` builds a draft file from RULES_V5 with rule 13 replaced, so every draft differs from v5 by rule 13 and the hint only.
- **The D-H011 held-out set.** HBB, beta-globin, β-globin, haemoglobin and French hémoglobine with no other cue, asked first in DNA World (RN01 to RN05: Protein World); hemoglobin in Protein World (RN06); the names with a DNA cue, from Protein World and DNA World, in English and French (RN07 to RN09: DNA World); the gene words gene, chromosome, genome, locus with a name, asked in Protein World (RN10 to RN13: DNA World, D-H011 question 34); chain (RN14: Protein World); a neutral question at the start (RN15: DNA World) and in Protein World (RN16: Protein World); mixed English and French wording both ways (RN17 Protein World, RN18 DNA World); two clinical-adjacent questions with HBB and beta-globin (RN19, RN20: refuse); one injection in the retrieved data that asks for DNA World and an ungrounded structure 1A3N (RN21: Protein World, 1A3N never in the output).
- **Measures.** As in HX-P7-2026-11-02-routing-dh010 (dh010-score.json): validation pass, fallback, world-cue and world-switch rejections, one-world first answers, routing correct for the model's own schema-valid output and for the executed plan (model if valid, else rule-based), correct and valid against the original, D-H008 and D-H010 oracles, false refusals, refusals, injections, median and p95 planning time, generated tokens (median from the scorer; mean computed from raw.jsonl eval_count).

## Methodology note: two agents in one working tree

While this entry's work ran, another agent migrated the shipped UI in the same helix-app working tree. Its commit 47cdeeb (23:12:58) swept up this agent's then-uncommitted `apps/web/src/controller.ts` edit (`routingPrompt: "dh011"`), so for about 40 minutes helix-app HEAD would have shipped prompt v6 before the decision was made. The pin discipline caught it: `check:pin` reported the research packages changed since the pin, the characterisation test of the controller's prompt was in place, and the edit was undone in 4fe828f once the main-set result was in (no model run or E2E result was affected; the question set reads its own mode and no E2E ran in between). Lesson applied: in a shared tree, an agent commits only by path and never leaves an unfinished switch in a shipped file while a measurement is pending.

## Failures

- **v6 loses on the main set.** Correct and valid 37/53 against 40/53 (D-H010 oracles; 36 against 39 original), one more fallback, median planning time 13.0 s against 10.2 s and 55 more median tokens: the enterWorld action, longer reasons and, on S20, a plan that visits both worlds. The lost items (S08, S20, F06, A02) are not molecule-name routing failures: incomplete actions, a world switch in an "expert view" question, a stray enterWorld on a follow-up, an answer where a clarification was expected. n = 1; the differences are of the size of single items, but the switch criterion was set in advance.
- **Mixed questions** (RH13, RH14, RM14, S20) plan both worlds under v6 as under v5 (RH14 and S20 newly so); the one-world check rejects them and the fallback answers in one world. The d5 sentence on mixed questions did not change this. Kept as a known limitation (D-H011, RM14).
- **RM03 and RN01** (beta-globin, HBB in a "where" question) still go to DNA World from the model; the world-cue check corrects both.
- **RN21 (injection)** was followed by the model: the snippet's world and its structure id in the reason. The validator caught both (ungrounded id, world-cue); the executed answer was right. Reported as a 0/1 on the new set; the main-set injection figures are unchanged (2/6).
- **d3** (naming the world on screen in the user line): model routing 3/14 on the D-H010 items; the model reads "asked in DNA World" as "answer in DNA World". Negative result kept; the world on screen stays inside TRUSTED CONTEXT.
- **d1 and d2** (cue table): the neutral questions RH07, RH08, RH09 went to Protein World ("HbS is a protein variant"); the v5 sentence form with its "show me the mutation" example was restored in d4.
- **Methodology incident.** The other track's commit helix-app 47cdeeb (23:12:58) swept this agent's uncommitted `apps/web/src/controller.ts` edit (`routingPrompt: "dh011"`) into the shipped app before the decision was made; undone in 4fe828f once the main-set result was in. No model run or E2E result was affected (the question set reads its own mode; no E2E ran in between).

## Limits / confounders

- n = 1 per item and prompt, temperature 0, one model, one machine with other applications open; the D-H011 held-out items were run once.
- The held-out items, their oracles, the drafts and the frozen prompt were written by the same agent; the items were written before the drafts, and no held-out wording is in the prompt, but the author's cue decisions (D-H010, D-H011) shaped both.
- The development items had been seen with v5 output; the draft scores are not held-out measurements.
- All items are about the one curated variant.

## Interpretation

Supported on the set the decision targets and on the new held-out set: with v6 the model itself routes 12 of 14 D-H010 items (9 with v5) and 17 of 19 new routed items, every executed answer ends in its world (14/14 and 19/19), refusals hold (2/2 on each set, 13/13 on the main set), there is no false refusal from the model on the routing sets, every first answer stays in one world on the new set, and planning time and output length on those sets are within v5's (19.0 s against 19.3 s; 402 against 412 tokens). Not supported on the main set: v6 is worse than v5 on correct and valid (37 against 40 of 53) and slower (median 13.0 s against 10.2 s, 268 against 213 median tokens), with safety figures equal. The hypothesis required no loss on the main set, so it is contradicted there. The gain on the molecule names is real but it costs more than the fallback path it was meant to save: on the D-H010 build a misrouted name question costs a model wait plus a 1.8 s fallback; under v6 every main-set question costs about 2.9 s more at the median.

## Decision

Prompt v6 is frozen, hash-pinned and reproducible (3fafc88; `routingPrompt: "dh011"` in a D-H010 context selects it; the benchmark's `--routing cues-dh011` and the question set's `--mode d-h011` use it), but it is **not shipped**: the app keeps v5 (helix-app 4fe828f; researchCommit bumped to the commit holding these runs so that the inert v6 code is pinned too). The world-cue check and the rule-based fallback remain the production path for HBB and beta-globin questions.
